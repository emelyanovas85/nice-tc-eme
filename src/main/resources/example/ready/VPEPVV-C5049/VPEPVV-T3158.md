## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3158** в текущем виде **не готов к автоматизации** из-за фундаментальных нарушений принципов построения автотестов. Ключевой проблемой является нарушение принципа **Единой ответственности**: один тест-кейс пытается покрыть 8 различных сценариев негативного тестирования, что делает его громоздким, недетерминированным и сложным в поддержке. Дополнительно, тест-кейс содержит **логические ветвления** в шагах, **неконкретные ожидаемые результаты** (вариативность статусов, отсутствие четких масок), а также требует **ручной подготовки данных** (шифрование, подпись), что невозможно выполнить в рамках автоматизированного прогона без выноса логики в код. Вложенный тест-кейс **VPEPVV-T3159** также имеет критические нарушения структуры (наличие предварительных действий).

**Рекомендации по устранению:**

1.  **Декомпозиция тест-кейса:** Разделить VPEPVV-T3158 на **8 отдельных тест-кейсов**, каждый из которых будет проверять только один конкретный тип ошибки (например, "Пустой архив", "Отсутствует доверенность" и т.д.). Это обеспечит выполнение принципа Единой ответственности.
2.  **Устранение недетерминированности:**
    *   Убрать логические ветвления в шагах (выбрать один способ загрузки файла, например, через API или скрытый input).
    *   Заменить вариативные ожидаемые результаты ("<заполнено одним из...>") на конкретные проверки для каждого нового тест-кейса.
    *   Переформулировать шаги ожидания и проверки как обязательные действия, убрав условности ("для АТ можно...").
3.  **Автоматизация подготовки данных:**
    *   Описать шаги шифрования и формирования подписи через вызовы API или скрипты, которые будут выполняться автоматически в начале теста.
    *   Убрать ручные операции из раздела "Предварительные действия".
4.  **Исправление работы с данными и вложениями:**
    *   Удалить неиспользуемые колонки из "Наборов тестовых данных" ("Форма", "Тема сообщения", "Дефект") или начать их использовать в шагах.
    *   Очистить колонки данных от описаний действий и ссылок на дефекты.
    *   Привести в соответствие список вложений и тестовых данных: добавить отсутствующие файлы .zip.enc или изменить данные на использование существующих .zip.
    *   Добавить во вложения **эталонные файлы** (status.xml, ESODReceipt.xml) для каждого сценария, чтобы выполнить требование к сравнению файлов.
5.  **Доработка вложенного ТК (VPEPVV-T3159):** Очистить раздел "Предварительные действия" от любого содержимого, перенеся логику авторизации в шаги основного теста или в фикстуры фреймворка.
6.  **Статусная модель:** Перевести тест-кейс в статусы "Утвержден" и "АТ принят", а также обеспечить его прохождение и фиксацию статуса "Пройден" для актуализации дат.

Только после выполнения этих действий тест-кейс (вернее, группа новых тест-кейсов) сможет считаться готовым к автоматизации.
