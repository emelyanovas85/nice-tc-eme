## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **ASLUNOHOD-T32** в текущем виде **не готов к автоматизации** из-за фундаментальных нарушений в трех ключевых областях:
1.  **Недетерминированность:** Сценарий зависит от ответа внешнего модуля ИИ, что делает результат непредсказуемым при повторных запусках.
2.  **Отсутствие конкретики в шагах и данных:** Шаги описаны общими фразами без конкретных значений параметров, имен файлов и типов UI-элементов. Блок "Вложения" пуст, хотя тест требует загрузки файла.
3.  **Нарушение принципов оформления:** Массовое использование непроверенных аббревиатур (АТК, ИТС), отсутствие расшифровок, некорректные статусы выполнения и отсутствие проверки начального состояния системы.

**Рекомендации по устранению:**
1.  **Изоляция от ИИ:** Заменить реальный вызов ИИ на мок-объект с фиксированным ответом либо изменить проверку на наличие любого ответа без валидации его содержания.
2.  **Параметризация и данные:**
    *   Добавить конкретные значения во все шаги (URL, имена моделей, тексты запросов).
    *   Создать и прикрепить эталонный файл (PDF/DOCX) во вложения, указать его имя в шаге 5.
    *   Добавить эталонный файл ожидаемого результата (JSON/XML) для шага 6/9.
3.  **Детализация UI:** Переписать все ожидаемые результаты, явно указывая тип элемента (модальное окно, текстовое поле, таблица) и конкретное ожидаемое состояние (видимость, текст, значение).
4.  **Исправление статусов и предусловий:**
    *   Установить статус ТК в "Утвержден" / "АТ принят".
    *   Провести ручной прогон, зафиксировать статус "Пройден".
    *   Добавить блок "Предварительные действия" с указанием учетных данных, необходимого ПО и проверки начального состояния через API.
5.  **Терминология:** Расшифровать все аббревиатуры (АТК, ИТС, ТК) при первом упоминании или в начале документа.

После устранения указанных замечаний уровень готовности тест-кейса возрастет до допустимого для автоматизации.
