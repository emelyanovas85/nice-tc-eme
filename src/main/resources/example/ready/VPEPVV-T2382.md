## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T2382** имеет критические структурные нарушения, делающие его непригодным для прямой автоматизации в текущем виде. Главной проблемой является **нарушение принципа атомарности и единой ответственности**: один тест-кейс агрегирует проверку более 15 различных полей формы путем последовательного вызова других тест-кейсов (шаги 1-19), при этом **отсутствуют явные ожидаемые результаты** для этих шагов в контексте основного теста. Дополнительно, все **вложенные тест-кейсы** (VPEPVV-T2358, VPEPVV-T2691 и др.) содержат критическое нарушение формата: у них заполнен блок **"Предварительные действия"**, который для вложенных ТК должен быть абсолютно пустым. Также тест-кейс не имеет необходимых статусов ("Утвержден", "АТ принят", "Пройден").

**Рекомендации по устранению:**
1.  **Декомпозиция или Параметризация:** Разбить тест-кейс VPEPVV-T2382 на отдельные атомарные тест-кейсы для каждого проверяемого поля (Дата, Номер дела, Сумма иска и т.д.) либо реализовать единый параметризованный тест (Data-Driven), где набор данных будет содержать информацию о поле, входных значениях и ожидаемых результатах. Избегать последовательного вызова других ТК как шагов без явной передачи статуса и результатов.
2.  **Очистка вложенных ТК:** Во всех вложенных тест-кейсах (VPEPVV-T2358, VPEPVV-T2691, VPEPVV-T2695, VPEPVV-T2699, VPEPVV-T2776, VPEPVV-T2694) **полностью очистить блок "Предварительные действия"**. Логику подготовки (авторизация, снятие фокуса) перенести в шаги основного теста или в механизмы фикстур/хуков фреймворка автоматизации.
3.  **Добавление Ожидаемых Результатов:** Для каждого шага (особенно 1-19) явно прописать ожидаемый результат, описывающий изменение состояния UI (тип элемента, текст сообщения, цвет рамки), а не полагаться на успешное выполнение вложенного ТК.
4.  **Исправление Статусов:** Провести ручной прогон тест-кейса, зафиксировать результаты и перевести ТК в статусы "Утвержден" и "АТ принят". Убедиться, что дата последнего прохождения не старше 14 рабочих дней.
5.  **Работа с Данными:** Удалить неиспользуемые колонки из наборов тестовых данных ('Форма', 'Блок 1') или начать использовать их как параметры в шагах. Убрать нумерацию ('№1') из значений параметров, перенеся её в логику теста.
