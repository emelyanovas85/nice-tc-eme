## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3023** в текущем виде **категорически не готов к автоматизации**. Критическими проблемами являются:
1.  **Нарушение изоляции:** Зависимость от внешних тест-кейсов (авторизация, подготовка сертификатов) и наличие ссылок на выполнение других ТК внутри параметров данных.
2.  **Недетерминированность:** Наличие шагов с ручным обновлением страницы (F5) и ожиданием "пока не изменится", что невозможно реализовать в автотесте без явных механизмов ожидания (explicit waits).
3.  **Взаимодействие с ОС:** Шаги, требующие работы с проводником Windows (выбор файлов, открытие папок, чтение XML с диска), что выходит за рамки UI-автоматизации браузера.
4.  **Отсутствие четкости в ожиданиях:** Не указаны типы UI-элементов, используются динамические данные без масок, дублируется логика проверок.
5.  **Административные нарушения:** Тест не имеет требуемых статусов ("Утвержден", "АТ принят") и просроченную дату последнего прохождения.

**Рекомендации по устранению:**

1.  **Декомпозиция (Разбиение теста):**
    *   Разделить текущий сценарий на 3-4 независимых теста:
        *   ТК 1: Создание черновика пакета и добавление файлов.
        *   ТК 2: Отправка пакета и проверка смены статусов (с явными ожиданиями).
        *   ТК 3: Скачивание и валидация квитанций (проверка XML через API или скрипт, а не через UI проводника).
    *   Это обеспечит выполнение принципа **Единой ответственности**.

2.  **Устранение зависимостей и ручных шагов:**
    *   Убрать шаг "Выполнить тест id = ...". Реализовать авторизацию через API или прямые действия UI внутри каждого теста.
    *   Заменить инструкции "обновлять страницу (F5)" на **Explicit Waits** (ожидание изменения текста/атрибута элемента).
    *   Исключить взаимодействие с проводником ОС. Загрузку файлов реализовать через прямой путь к файлу в поле `input type="file"`. Проверку скачанных файлов реализовать через чтение файловой системы на стороне тестового агента (не описывая это как шаги UI-теста) или через API бэкенда.

3.  **Исправление тестовых данных и ожиданий:**
    *   Очистить колонки тестовых данных от глаголов и ссылок на ТК ('Выполнить...', 'Включить'). Оставить только данные (имена файлов, булевы флаги, строки).

    *   Добавить недостающие файлы (.enc, .sig) во вложения и явно указать имена эталонных XML файлов для сравнения в шагах валидации.
    *   Использовать регулярные выражения или маски для проверки динамических дат в именах файлов и путях.

4.  **Административные правки:**
    *   Обновить статус тест-кейса на "Утвержден" и "АТ принят".
    *   Провести ручное прохождение теста, зафиксировать статус "Пройден" актуальной датой.
    *   Добавить в предварительные действия требование к установленному ПО (КриптоПро CSP).
