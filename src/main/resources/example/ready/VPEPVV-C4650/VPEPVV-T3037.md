## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3037** в текущем виде **не пригоден для автоматизации**. Критическими препятствиями являются:
1.  **Нарушение принципа единой ответственности:** Тест покрывает слишком сложный составной сценарий (создание, ошибка, исправление, успешная отправка), что делает его хрупким и сложным в отладке.
2.  **Зависимость от ручных действий и ОС:** Наличие инструкций по нажатию клавиши **F5** для обновления страницы и взаимодействие с **нативным диалогом выбора файлов** (проводник ОС) делает тест невозможным для выполнения в автоматическом режиме без полной переписки шагов.
3.  **Недетерминированность:** Ожидаемые результаты содержат вариативные формулировки ("текст может отличаться"), что не позволяет написать стабильные ассерты.
4.  **Отсутствие типизации UI:** В ожидаемых результатах не указаны типы элементов (кнопка, поле, модальное окно), что необходимо для корректного написания селекторов.
5.  **Статусная дисциплина:** Тест-кейс не имеет утвержденных статусов ("Утвержден", "АТ принят") и истории успешных прогонов ("Пройден").

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разбить тест-кейс на три независимых атомарных теста:
    *   ТК А: Отправка пакета с ошибкой валидации (проверка негативного сценария).
    *   ТК Б: Редактирование пакета (удаление/добавление файлов) в состоянии "Ошибка".
    *   ТК В: Успешная отправка исправленного пакета (позитивный сценарий).
2.  **Устранение ручных шагов:** Заменить все упоминания "обновить страницу (F5)" на механизмы **явного ожидания (Explicit Wait)** изменения статуса элемента. Исключить взаимодействие с проводником ОС, используя прямую передачу пути к файлу в методы загрузки.
3.  **Детализация ожидаемых результатов:** Переписать все ожидаемые результаты, указав **тип UI-элемента** (например, `Button "Отправить"`, `Input "Сертификат"`, `Modal "Ошибка"`). Заменить вариативные тексты ошибок на проверку стабильной части строки или регулярное выражение.
4.  **Работа с данными:** Удалить инструкции выполнения других тест-кейсов из блока "Параметры". Добавить недостающие файлы (.enc, .sig) во вложения или настроить их генерацию в предусловиях.
5.  **Статусная модель:** Провести ручное прохождение тест-кейса (или его декомпозированных частей), зафиксировать результат "Пройден" и перевести статусы в "Утвержден" и "АТ принят".
