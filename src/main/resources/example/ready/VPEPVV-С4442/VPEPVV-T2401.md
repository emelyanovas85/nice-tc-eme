## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T2401** не готов к автоматизации в текущем виде из-за нарушения фундаментальных принципов автоматизированного тестирования:
1.  **Отсутствие атомарности и единой ответственности:** ТК выступает как "оркестратор", запускающий набор других тестов (шаги 1-5), вместо проверки одного конкретного сценария. Это делает его нестабильным и сложным в отладке.
2.  **Отсутствие верифицируемых ожидаемых результатов:** В ключевых шагах (1-5) колонка "Ожидаемый результат" пуста. Автоматизация не может подтвердить успешность шага, так как критерии успеха не описаны явно в данном ТК.
3.  **Нарушение работы с данными:** Параметры из наборов данных не используются в шагах через механизм подстановки, а зашиты статическим текстом. В данных присутствуют описания действий, а не чистые значения.
4.  **Статусная модель:** ТК не имеет требуемых статусов ("Утвержден", "АТ принят") и не имеет успешных прогонов ("Пройден"), что блокирует его включение в регрессионную сборку.
5.  **Проблемы во вложенных кейсах:** Все проанализированные вложенные тест-кейсы (VPEPVV-T2691, T2358, T2695, T2694) имеют критическое нарушение требования 9.1 — наличие текста в блоке "Предварительные действия", что недопустимо для вложенных сценариев.

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разделить VPEPVV-T2401 на отдельные атомарные тест-кейсы. Каждый кейс должен проверять валидацию конкретного поля (Дата, Наименование, ФИО и т.д.) самостоятельно, без вызова внешних ТК в шагах.
2.  **Описание ожидаемых результатов:** Для каждого шага явно прописать ожидаемый результат, указывая:
    *   Тип UI-элемента (поле ввода, кнопка, модальное окно).
    *   Конкретное состояние (выделено красным, текст ошибки равен "...", элемент скрыт).
3.  **Исправление параметризации:**
    *   Заменить статические вхождения '{Форма}', '{Блок 1}' на синтаксис подстановки параметров.
    *   Удалить из значений параметров глаголы и описания действий, оставив только данные.
4.  **Очистка вложенных ТК:** Во всех вложенных тест-кейсах полностью очистить раздел "Предварительные действия". Инструкции по снятию фокуса и работе с символами перенести в шаги тест-кейса или в код автоматизации (хелперы).
5.  **Статусная дисциплина:** Провести ручной прогон обновленных тест-кейсов, проставить статус "Пройден" и изменить статус ТК на "Утвержден" / "АТ принят".
6.  **Добавление предусловий:** Добавить шаг проверки начального состояния системы (через API или БД) перед началом тестирования формы.

Только после выполнения этих действий тест-кейс сможет считаться готовым к надежной автоматизации.
