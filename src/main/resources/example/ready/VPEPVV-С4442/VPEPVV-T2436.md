## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T2436** представляет собой сценарий регрессионного набора ("набор тест-кейсов"), а не атомарный тест, что фундаментально противоречит принципам автоматизации (Атомарность, Единая ответственность). Он состоит преимущественно из вызовов других тест-кейсов без собственных явных проверок (отсутствуют ожидаемые результаты в 18 из 18 шагов), что делает его непрозрачным и хрупким. Дополнительно выявлены критические нарушения в статусе документа (не утвержден, нет прохождений) и наличии неиспользуемых тестовых данных.

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разделить данный тест-кейс на отдельные атомарные тесты для каждой проверяемой функциональности (валидация даты, проверка длины строки, динамическое добавление полей и т.д.). Каждый новый тест должен иметь собственные шаги и явные ожидаемые результаты.
2.  **Добавление ассертов:** Если сохранение структуры набора необходимо, в каждый шаг "Выполнить тест" необходимо добавить конкретный ожидаемый результат, описывающий изменение состояния UI или данных после выполнения вложенного сценария.
3.  **Исправление статусов:** Провести ручной прогон тест-кейса, утвердить его и проставить статусы "Утвержден" и "АТ принят".
4.  **Очистка данных:** Удалить неиспользуемые колонки из набора тестовых данных ('№', 'Форма', 'Блок 1') или начать их использовать в шагах через параметризацию.
5.  **Уточнение шагов:** Заполнить пустой шаг 3 конкретным действием и проверкой. Расшифровать предметные аббревиатуры (ОГРН и др.) в шагах 6 и 18. Указать типы UI-элементов в ожидаемых результатах.
