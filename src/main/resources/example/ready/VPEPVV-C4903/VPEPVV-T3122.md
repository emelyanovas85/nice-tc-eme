## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3122** в текущем виде **не готов к надежной автоматизации** из-за фундаментальных нарушений принципов построения автотестов. Ключевые проблемы:
1.  **Нарушение принципа единой ответственности:** Тест пытается проверить структуру фильтров для 14 различных столбцов в одном сценарии, что делает его громоздким (36 шагов) и сложным в отладке.
2.  **Массовое дублирование шагов и проверок:** Логика проверки фильтров повторяется 14 раз с минимальными изменениями, что нарушает требование 3.3 и 5.3.
3.  **Низкая детерминированность:** Использование проверки "текущей даты" в ожидаемых результатах (шаги 15, 18, 21, 24) приведет к нестабильности тестов при запуске в разное время.
4.  **Некорректное описание шагов и ожидаемых результатов:** Отсутствие конкретных локаторов, нарушение атомарности шагов (несколько действий в одном), отсутствие указания типов UI-элементов в ожидаемых результатах (требования 3.1, 4.1, 5.2).
5.  **Нарушение процессных требований:** Тест-кейс не имеет необходимых статусов ("Утвержден", "АТ принят") и просрочен по дате последнего прохождения (более 14 рабочих дней).

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разделить данный тест-кейс на несколько атомарных тестов. Например:
    *   Один тест для проверки текстовых фильтров (параметризованный по имени столбца).
    *   Один тест для проверки фильтров по датам.
    *   Один тест для проверки числовых фильтров/списков.
2.  **Параметризация:** Вместо копирования шагов для каждого столбца использовать параметризованный подход: один набор шагов, который выполняется в цикле по списку столбцов из тестовых данных.
3.  **Исправление детерминированности:** Заменить проверку "текущей даты" на проверку конкретной статической даты или передавать ожидаемую дату через параметры теста.
4.  **Детализация шагов:**
    *   Переписать шаги, явно указывая объекты взаимодействия (например, "Нажать кнопку 'Фильтр' в заголовке столбца 'Тема сообщения'").
    *   Разделить составные шаги (клик по пустому месту + клик по иконке) на отдельные атомарные шаги.
    *   В ожидаемых результатах явно указывать тип элемента (например, "Выпадающий список (тип: dropdown) содержит значения...").
5.  **Устранение дублирования проверок:** Оставить полную проверку значений выпадающего списка только в одном шаге (например, для первого столбца), в остальных шагах проверять только факт открытия списка или наличие ключевых элементов.
6.  **Актуализация статусов:** Провести повторное прохождение теста, обновить статусы на "Утвержден" и "АТ принят", убедиться, что дата прохождения актуальна (не старше 14 рабочих дней).
7.  **Очистка предварительных действий:** Убрать логику "if/else" и ссылки на другие ТК/дефекты из блока предварительных действий, формализовав необходимые действия в виде линейных шагов. Добавить проверку начального состояния через API/БД.

Только после выполнения данных рекомендаций тест-кейс сможет считаться пригодным для стабильной автоматизации.
