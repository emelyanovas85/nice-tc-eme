## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3116** в текущем виде **не готов к автоматизации** из-за фундаментальных нарушений принципов детерминированности, четкости проверок и управления данными. Ключевые блокирующие факторы:
1.  **Недетерминированность:** Использование динамических дат (`<текущий день>`, `<первая пятница декабря...>`) в шагах и данных делает результат теста зависимым от времени запуска, что недопустимо для автотестов.
2.  **Отсутствие четких проверок:** Ожидаемые результаты сформулированы субъективно ("показываются только значения..."), без указания конкретных UI-элементов (типов и состояний) и без проверки реальных данных в таблице. Это делает невозможным создание надежных ассертов.
3.  **Нарушение управления данными:** Тест зависит от предустановленных данных в среде, которые не создаются и не очищаются в рамках кейса. Наличие пустых полей (`<не заполняем>`) и смешение типов данных (строки, даты, логические операторы) в одном столбце усложняет параметризацию.
4.  **Избыточность и ветвления:** Наличие логических ветвлений ("в противном случае", "можно как... так и...") и многократное открытие/закрытие окон фильтра без явной необходимости замедляют тест и усложняют его поддержку.
5.  **Статусная дисциплина:** Тест-кейс не имеет утвержденного статуса и успешных прогонов, что формально запрещает его передачу в автоматизацию.

**Рекомендации по устранению:**
1.  **Фиксация данных:** Заменить все динамические даты на фиксированные значения или реализовать механизм мокирования времени на уровне тестового фреймворка. Вынести подготовку тестовых данных (создание записей с нужными атрибутами) в предварительные действия через API.
2.  **Детализация проверок:** Переписать все ожидаемые результаты, явно указывая:
    *   Тип UI-элемента (кнопка, поле ввода, таблица, ячейка).
    *   Ожидаемое состояние (активен, содержит текст, отсортирован по возрастанию).
    *   Конкретные значения для проверки (например, "Таблица содержит 3 строки, в столбце 'Дата' все значения >= 01.01.2023").
3.  **Рефакторинг шагов:**
    *   Убрать все логические ветвления, зафиксировав один сценарий выполнения (например, только ввод даты с клавиатуры).

    *   Убрать дублирование проверок структуры окна (шаги 3, 5, 8, 10), оставив только критически необходимые.
