## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3121** имеет критические недостатки, препятствующие его эффективной автоматизации. Главной проблемой является **нарушение принципа единой ответственности и избыточность шагов**: тест пытается проверить структуру фильтров для 7 различных столбцов в одном сценарии, что приводит к многократному дублированию однотипных действий (открытие/закрытие окон, проверка списков). Это делает тест громоздким, сложным в поддержке и диагностике.
Дополнительно выявлены проблемы с **детерминированностью** (использование "текущей даты" без параметризации) и **четкостью ожидаемых результатов** (отсутствие типов UI-элементов и проверок данных в таблицах/полях). Также тест не соответствует требованиям по статусам и актуальности прохождения.

**Рекомендации по устранению:**
1.  **Декомпозиция теста:** Разделить данный тест-кейс на несколько атомарных тестов. Например, создать один параметризованный тест или отдельные тесты для проверки фильтров по текстовым полям, датам, числам и статусам. Это обеспечит принцип единой ответственности.
2.  **Устранение дублирования:** Использовать параметризацию или циклы для проверки однотипных элементов (выпадающие списки, структура окон). Убрать повторяющиеся последовательности действий "закрыть -> открыть" из явного описания шагов, перенеся эту логику в код автотеста или вспомогательные функции.
3.  **Детерминированность:** Заменить проверку "текущей даты" на использование переменной окружения или вычисляемой даты ({CurrentDate}), либо зафиксировать конкретную дату для теста.
4.  **Уточнение ожидаемых результатов:**
    *   Для каждого шага явно указать **тип UI-элемента** (Dropdown, Input, Button, Label) и его **наименование/селектор**.
    *   Добавить проверки **данных** (содержимое строк таблицы, значения в полях ввода), а не только наличие элементов.
    *   Исправить дублирование значений в списке статусов (шаг 19).
5.  **Исправление предварительных условий:**
    *   Удалить гиперссылки на другие ТК и дефекты из описания.
    *   Убрать логические ветвления ("если/иначе"), вынеся настройку чек-боксов в отдельный обязательный шаг или скрипт подготовки.
    *   Добавить проверку начального состояния через API/БД.
6.  **Актуализация статусов:** Перевести тест-кейс в статусы "Утвержден" и "АТ принят", а также актуализировать дату последнего прохождения (не старше 14 дней).
