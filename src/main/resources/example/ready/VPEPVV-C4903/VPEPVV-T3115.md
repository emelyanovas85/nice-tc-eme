## 4. Вывод и рекомендации

Основной проблемой тест-кейса **VPEPVV-T3115** является **низкая детерминированность и недостаточная конкретизация шагов и ожидаемых результатов**, что делает его непригодным для стабильной автоматизации в текущем виде.

**Ключевые проблемы:**
1.  **Нарушение детерминированности:** Использование динамических дат (`<текущая дата>`, `<предыдущий год>`) без четкого алгоритма генерации и отсутствие подготовки тестовых данных (создание сообщений с нужными атрибутами) делают тест зависимым от "грязного" окружения.
2.  **Отсутствие атомарности и избыточность:** Шаги смешивают действия и сложные проверки множества UI-элементов. Многократное повторение циклов "открыть фильтр – проверить – закрыть" (шаги 3, 5, 8, 10) создает избыточность и увеличивает время выполнения без добавления ценности.
3.  **Неконкретные ожидаемые результаты:** Фразы типа "Текст: Значение", "показываются значения, соответствующие условию" и отсутствие указания типов UI-элементов (кнопка, поле, лейбл) не позволяют написать однозначные ассерты.
4.  **Логические ветвления:** Наличие условий в шагах ("В случае заполнения... можно как... так и...") нарушает линейность сценария.
5.  **Статусная дисциплина:** Тест-кейс имеет статус "На согласование", что блокирует его использование в автоматизации.

**Рекомендации по устранению:**
*   **Подготовка данных:** Добавить в предварительные действия шаг создания тестовых данных через API (сообщения с конкретными датами, статусами и текстом) и проверку их наличия.
*   **Фиксация данных:** Заменить динамические вычисления в таблице данных на конкретные значения или переменные окружения, вычисляемые кодом теста.
*   **Декомпозиция:** Разделить тест на несколько меньших тест-кейсов (например, отдельно проверка текстового фильтра, отдельно фильтра по дате), чтобы обеспечить принцип единой ответственности.
*   **Детализация шагов:** Переписать ожидаемые результаты, указывая тип элемента и конкретное ожидаемое значение/состояние (например, "Таблица содержит 3 строки", "Значение в ячейке A1 равно 'X'"). Убрать логические ветвления, оставив один сценарий.
*   **Оптимизация:** Убрать избыточные шаги повторного открытия окна фильтра, оставив проверку состояния непосредственно после действия.
*   **Смена статуса:** После внесения правок перевести тест-кейс в статус "Утвержден".
