## 4. Вывод и рекомендации

Основной проблемой тест-кейса **VPEPVV-T3135** является **нарушение принципа единой ответственности и наличие логических ветвлений внутри шагов**, что делает его непригодным для линейной автоматизации в текущем виде. Тест пытается покрыть два разных сценария (работа с открытыми и зашифрованными данными) в одном прогоне, используя условную логику в шагах и данных.

**Ключевые проблемы:**
1.  **Логика в данных и шагах:** Использование колонки "Выполнение расшифрования" для управления потоком теста (шаг 8) и смешение инструкций для ручного и автоматизированного тестирования в одном шаге.
2.  **Взаимодействие с ОС:** Шаги требуют открытия папки загрузки и работы с нативным ПО (КриптоАРМ), что требует вынесения в отдельные утилиты или изменения архитектуры теста (проверка через ФС без UI).
3.  **Нечеткие ожидаемые результаты:** Отсутствие указания типов UI-элементов, динамические данные (время) в ожидаемых результатах без использования паттернов.
4.  **Статус и вложения:** ТК не имеет утвержденного статуса и необходимых эталонных файлов во вложениях.
5.  **Вложенный ТК (VPEPVV-T3134):** Нарушает требование к пустоте блока "Предварительные действия".

**Рекомендации:**
1.  **Разделить тест-кейс:** Создать два отдельных ТК: один для проверки скачивания открытых данных, второй — для скачивания и расшифрования конфиденциальных данных.
2.  **Убрать ветвления:** Исключить условные конструкции из шагов. Логика "если зашифровано, то расшифровать" должна реализовываться через разные тест-кейсы или теги, а не через подстановку текста действия из данных.
3.  **Изолировать работу с файлами:** Убрать шаги открытия проводника. Реализовать проверку скачанных файлов через прямое обращение к файловой системе в коде автотеста. Вынести процедуру расшифровки в отдельный хелпер/утилиту.
