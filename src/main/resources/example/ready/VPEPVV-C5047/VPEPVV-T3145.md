## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3145** в текущем виде **не готов к автоматизации** из-за фундаментального нарушения принципов атомарности и единой ответственности. Кейс пытается проверить 4 различных сценария валидации в одном прогоне, что приводит к дублированию шагов (7-14), неявным логическим ветвлениям в тестовых данных (`<Не добавляем>`, ссылки на другие ТК) и перегруженным шагам, содержащим по 3 действия одновременно (очистка, заполнение, клик). Кроме того, критически не проработана часть ожидаемых результатов: отсутствуют типы UI-элементов для сообщений об ошибках, используются плейсхолдеры `{0}` вместо конкретных значений, а статусы тест-кейса не соответствуют требованиям жизненного цикла (отсутствуют статусы "Утвержден" и "АТ принят").

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разделить текущий тест-кейс на 4 отдельных атомарных тест-кейса, каждый из которых проверяет один конкретный сценарий валидации (обязательные поля, отсутствие сертификата, неверная подпись, неверное расширение).
2.  **Очистка шагов:**
    *   Разбить составные шаги (очистка + заполнение + клик) на отдельные атомарные действия.
    *   Убрать логику и условия (`<Не добавляем>`, `Выполнить ТК...`) из колонки "Тестовые данные". Перенести выполнение дочерних сценариев в отдельные шаги или предварительные условия.
    *   Явно указывать имена контролов в тексте шага, а не только в данных.
3.  **Детализация проверок:**
    *   В ожидаемых результатах указывать тип UI-элемента (например, "Блок уведомлений", "Поле ввода", "Кнопка").
    *   Заменить плейсхолдеры `{0}` на конкретные значения или параметризовать проверку строки сообщения.
4.  **Работа с данными:**
    *   Удалить лишний файл `File.doc` из вложений.
    *   Обеспечить корректное использование параметров (колонка `Форма` должна подставляться в шаг через `{Форма}`).
5.  **Статусная модель:** Перевести тест-кейс в статус "Утвержден" и проставить статус "АТ принят" после устранения замечаний. Добавить проверку начального состояния через API/БД.
