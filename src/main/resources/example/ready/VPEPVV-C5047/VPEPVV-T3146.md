## 4. Вывод и рекомендации

**Основная проблема:**
Тест-кейс **VPEPVV-T3146** категорически не готов к автоматизации в текущем виде из-за нарушения фундаментального принципа **Атомарности (Single Responsibility)**. В одном тесте попытаны реализовать 6 различных сценариев негативного тестирования (валидация разных типов ошибок). Это приводит к каскадным ошибкам: падение на первом сценарии блокирует проверку остальных, а множественные шаги очистки состояния внутри тела теста делают его недетерминированным и сложным в поддержке.

Дополнительно критичным является нарушение работы с **Тестовыми данными**: в колонку данных внедрена логика действий (глаголы "нажать", "очистить", ссылки на другие ТК), что делает невозможным параметрический запуск теста фреймворком.

**Рекомендации по устранению:**
1.  **Декомпозиция:** Разделить текущий тест-кейс на **6 независимых атомарных тест-кейсов**, каждый из которых проверяет только один тип ошибки валидации (например, "Проверка ошибки при отсутствии файла формы", "Проверка ошибки при неверном расширении файла" и т.д.).
2.  **Очистка данных:** Переписать блок "Шаги" и "Наборы тестовых данных". Удалить из колонки данных все действия, глаголы и ссылки на другие ТК. Оставить там только чистые входные параметры (имена файлов, типы сертификатов). Действия вынести в текст шагов.
3.  **Детализация ожиданий:** Во всех шагах с проверкой ошибок явно указать **тип UI-элемента**, в котором отображается сообщение (например: "В *блоке уведомлений* отображается текст...", "В *поле ввода* подсветка красным...").
4.  **Статусная модель:** Провести ручное прохождение тест-кейса (или его новых атомарных версий), проставить статус "Пройден" и изменить общий статус на "Утвержден" / "АТ принят".
5.  **Предусловия:** Явно указать необходимость установленного ПО (КриптоПро CSP) в разделе предварительных действий и добавить проверку чистоты данных через API перед началом теста.
